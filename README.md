# Crypto Arbitrage Monitor

Private, cloud-oriented, read-only monitoring project. It does not place orders, accept offers, deposit, withdraw, transfer, or move funds.

## Intended five-step route

1. Money Storage: USDT -> ECR
2. BlackBit: ECR -> USDT (displayed `last_rate` only; indicative, not executable)
3. Winance: USDT -> ERUB (ERUB/USDT pair ID 18 only)
4. Sberkassa: ERUB -> RUB
5. Sberkassa: RUB -> USDT

Reference starting amount: 1000 USDT. Profit and ROI are calculated only after every quote is current and valid and all applicable fees are known. Unknown fees are never assumed to be zero. Money Storage's displayed commission is deliberately not deducted, per the agreed route definition. Arithmetic is denominated in USDT, not assumed to be exact USD.

## Agreed quote rules

### Money Storage: USDT -> ECR

- Use only `/deals#tab-3`, tab «Всем предлагают».
- The observed page-originated request must be `/public_deals/fetch?offset=0&limit=20&from=ECR&to=USDT`. Raw `src=ECR,dst=USDT` rows map to displayed USDT -> ECR.
- Average the first 20 matching offers in source order, or all if fewer. Do not remove older rows from this average and do not deduct commission.
- Freshness is independent: the newest returned offer's Unix `create_time` must be no more than 900 seconds old relative to the UTC cloud-runner collection time. Exactly 900 seconds is accepted. Future, missing, invalid, or older timestamps invalidate the quote.
- Read only the response generated by the authenticated page. Do not synthesize a second API request or retry 401/403/429.
- A protected offers page HTTP 200 and a successful offers payload are required to confirm access. An OAuth return URL or ordinary HTTP 200 is not authentication proof.

### BlackBit: ECR -> USDT

- Resolve exactly one ECR/USDT pair from `/site/currency_pairs`.
- Read only the pair's displayed `last_rate` from the order-book endpoint.
- Ignore order-book levels, volume, and liquidity. Mark the quote indicative; it is not an execution guarantee.

### Winance: USDT -> ERUB

- Use ERUB/USDT pair ID `18` only.
- Reject conflicting pair identity, missing, non-finite, zero, or negative rates.
- The provider supports explicit polling intervals from 900 to 3600 seconds. The intended hourly collection interval is 3600 seconds, but no recurring workflow is currently enabled.

### Sberkassa: ERUB -> RUB

- Use only `/deals#tab-3`, tab «Всем предлагают».
- The actual page-originated request must establish `from=ERUB&to=RUB`; request metadata can establish direction only when per-row currency IDs are not exposed.
- Use only `back_rate`; ignore `rate`.
- Average the first 20 correctly directed offers in source order, or all if fewer. Any missing, non-numeric, non-finite, zero, or negative selected `back_rate`, or an empty list, invalidates the quote.
- Freshness is independent from rate selection: at least one correctly directed offer must have a valid `create_time` within the preceding 900 seconds. Future or invalid timestamps do not prove freshness. Older offers are not filtered out of the first-20 average.
- Ignore fees, amounts, reserves, limits, volumes, liquidity, and partial execution.

### Sberkassa: RUB -> USDT

- Inspect `/exchange` separately.
- The actual numeric rate field and an independent successful-refresh freshness signal for this page must be established before this leg can be marked valid.
- Never reuse the `/deals` timestamp. HTTP Date, Last-Modified, ETag, browser clock, Age, or network timing alone do not prove that the displayed quote was refreshed.
- Do not infer a rate from an unverified field. The current probe collects sanitized candidate metadata only; this leg is not yet a validated quote provider.

## Collection and safety

- The common collector requires all five keys by default: `money_storage`, `blackbit`, `winance`, `sberkassa_sell`, and `sberkassa_exchange`.
- Each cycle is independent. A failed refresh makes that source unavailable for the cycle. Never backfill from an earlier snapshot or cache.
- The four-source diagnostic workflow intentionally ends in RUB. It must never report final USDT, profit, ROI, or a completed arbitrage route.
- CAPTCHA, E-ID, MFA, Cloudflare challenges, and device binding are not bypassed. A valid saved session may be reused; if the provider rejects it, automated collection stops safely and reports authentication required.
- Secrets, cookies, OAuth codes, authorization headers, and raw authenticated browser storage must never be written to logs, artifacts, or source control.
- Free infrastructure only. No paid VPS, paid API, subscription, paid fallback, or automatic upgrade.

## Current implementation status

Implemented:
- Decimal-based route calculation with explicit fee validation and stale/future quote rejection.
- Read-only BlackBit and Winance public API adapters.
- Money Storage authenticated page-response capture and normalized snapshot validation.
- Sberkassa ERUB -> RUB offer parsing, first-20 `back_rate` average, and 15-minute `create_time` freshness helper.
- Sberkassa browser diagnostics that separately inspect `/deals#tab-3` and `/exchange`.
- A common five-key quote collector that records per-source errors and never substitutes old quotes.
- Encrypted Chromium profile persistence, session-first browser startup, and a supervised E-ID fallback.
- Consolidated operating rules in [docs/OPERATIONS_STATUS.md](docs/OPERATIONS_STATUS.md).

Not yet complete:
- A confirmed current Money Storage session on a fresh runner. The last inspected run restored the encrypted profile but received HTTP 401 from `/account`; E-ID required a new interactive sign-in and Cloudflare challenge.
- A live validated Sberkassa ERUB -> RUB quote/freshness capture on the current integrated branch.
- A validated Sberkassa RUB -> USDT numeric field and independent freshness marker.
- One integrated five-source report workflow, a notification destination, and measured free-runner cost.
- Recurring hourly schedule. It remains intentionally disabled until every source is validated and the free-runtime budget is demonstrated.

## Intended schedule after validation

Hourly, 09:00 through 02:00 Astana time (Asia/Almaty, UTC+5), including both endpoints: 18 runs/day. Equivalent GitHub Actions cron: `0 4-21 * * *` UTC.

Each report must show all five route legs, direction, rate, UTC collection time, source freshness/status, and the reason for every unavailable source. Full-route final amount, profit, and ROI are permitted only when all five quotes are fresh and valid and all required fees are known. Otherwise the route is unavailable.

## Configuration

- `BLACKBIT_API_BASE_URL` (default: `https://blackbit.exchange/site`)
- `WINANCE_API_URL` (default: `https://winance.exchange/site/currency_pairs`)
- `WINANCE_POLL_SECONDS` (must be explicitly selected between 900 and 3600 before polling)
- `QUOTE_MAX_AGE_SECONDS` (must be explicitly selected after the polling cadence is chosen)
- `CHROMIUM_PROFILE_PASSPHRASE` (GitHub Actions secret; never place its value in source control or logs)
