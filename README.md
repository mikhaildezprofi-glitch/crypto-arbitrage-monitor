# Crypto Arbitrage Monitor

Public, cloud-oriented, read-only monitoring project. It does not place orders, accept offers, deposit, withdraw, transfer, or move funds.

## Intended five-step route

1. Money Storage: USDT -> ECR
2. BlackBit: ECR -> USDT (displayed `last_rate` only; indicative, not executable)
3. Winance: USDT -> ERUB (ERUB/USDT pair ID 18 only)
4. Sberkassa: ERUB -> RUB
5. Sberkassa: RUB -> USDT

Starting capital is a runtime setting and has not been fixed at 1000 USDT. All five route-fee defaults are temporarily 0% during collector development; this is not a statement that provider fees are actually zero. Ignore commissions displayed by the sites. Once all collectors work, the user will enter manual fee values in the calculator. Until then, any route result is a pre-fee estimate, not net profit. Arithmetic is denominated in USDT, not assumed to be exact USD.

## Agreed quote rules

### Money Storage: USDT -> ECR

- Use only `/deals#tab-3`, tab «Всем предлагают».
- The observed page-originated request must be `/public_deals/fetch?offset=0&limit=20&from=ECR&to=USDT`. Raw `src=ECR,dst=USDT` rows map to displayed USDT -> ECR.
- Average the first 20 matching offers in source order, or all if fewer. Do not remove older rows from this average and do not deduct commission.
- Freshness is independent: the newest returned offer's Unix `create_time` must be no more than 900 seconds old relative to the UTC cloud-runner collection time. Exactly 900 seconds is accepted. Future, missing, invalid, or older timestamps invalidate the quote.
- Read only the response generated by the authenticated page. Do not synthesize a second API request or retry 401/403/429.
- A protected offers page HTTP 200 and a successful offers payload are required to confirm access. An OAuth return URL or ordinary HTTP 200 is not authentication proof.

### BlackBit: ECR -> USDT

- Resolve exactly one ECR/USDT pair from `/site/currency_pairs`.
- Read only the pair's displayed `last_rate` from the order-book endpoint.
- Ignore order-book levels, volume, and liquidity. Mark the quote indicative; it is not an execution guarantee.

### Winance: USDT -> ERUB

- Use ERUB/USDT pair ID `18` only.
- Reject conflicting pair identity, missing, non-finite, zero, or negative rates.
- Winance is fetched once per collection cycle. The external scheduler controls cadence; the intended interval is hourly, but no recurring workflow is currently enabled.

### Sberkassa: ERUB -> RUB

- Use only `/deals#tab-3`, tab «Всем предлагают».
- The actual page-originated request must establish `from=ERUB&to=RUB`; request metadata can establish direction only when per-row currency IDs are not exposed.
- Use only `back_rate` and ignore `rate` completely. The quote is the arithmetic mean of the selected `back_rate` values.
- Average the first 20 correctly directed offers in source order, regardless of their creation times, or all if fewer. The quote is the arithmetic mean of `back_rate` for those offers. Any missing, non-numeric, non-finite, zero, or negative selected `back_rate`, or an empty list, invalidates the quote.
- Freshness is independent from rate selection: at least one correctly directed offer must have a valid `create_time` within the 15 minutes before collection (900 seconds). Future or invalid timestamps do not prove freshness. Older offers remain in the first-20 average regardless of their creation times.
- Ignore fees, amounts, reserves, limits, volumes, liquidity, and partial execution.

### Sberkassa: RUB -> USDT

- Inspect `/exchange` separately.
- The actual numeric rate field and an independent successful-refresh freshness signal for this page must be established before this leg can be marked valid.
- Never reuse the `/deals` timestamp. HTTP Date, Last-Modified, ETag, browser clock, Age, or network timing alone do not prove that the displayed quote was refreshed.
- If the page presents one published rate, use that single rate. If it presents multiple independent offers, validate their direction and apply the agreed first-20 averaging rule. Do not infer a rate from an unverified field. The current probe collects sanitized candidate metadata only; this leg is not yet a validated quote provider.

## Collection and safety

- The common collector requires all five keys by default: `money_storage`, `blackbit`, `winance`, `sberkassa_sell`, and `sberkassa_exchange`. It blocks non-GET quote requests for Money Storage and Sberkassa and fails closed when a quote method is not confirmed GET.
- Each cycle is independent. A failed refresh makes that source unavailable for the cycle. Never backfill from an earlier snapshot or cache.
- The four-source diagnostic workflow intentionally ends in RUB. It must never report final USDT, profit, ROI, or a completed arbitrage route.
- CAPTCHA, E-ID, MFA, Cloudflare challenges, and device binding are not bypassed. A valid saved session may be reused; if the provider rejects it, automated collection stops safely and reports authentication required.
- Secrets, cookies, OAuth codes, authorization headers, and raw authenticated browser storage must never be written to logs, artifacts, or source control.
- Free infrastructure only. No paid VPS, paid API, subscription, paid fallback, or automatic upgrade.

## Intended schedule after validation

Hourly, 09:00 through 02:00 Astana time (Asia/Almaty, UTC+5), including both endpoints: 18 runs/day. Equivalent GitHub Actions cron: `0 4-21 * * *` UTC.

Each report must show all five route legs, direction, rate, UTC collection time, source freshness/status, and the reason for every unavailable source. A route estimate is permitted only when all five quotes are fresh and valid. With temporary 0% fee defaults it is pre-fee only. A normalized pre-fee ROI may be shown per 1 USDT basis; net profit and net ROI require manual fee configuration. Otherwise the route is unavailable.

## Configuration

- `BLACKBIT_API_BASE_URL` (default: `https://blackbit.exchange/site`)
- `WINANCE_API_URL` (default: `https://winance.exchange/site/currency_pairs`)
- `QUOTE_MAX_AGE_SECONDS` (must be explicitly selected after the polling cadence is chosen)
- `CHROMIUM_PROFILE_PASSPHRASE` (GitHub Actions secret; never place its value in source control or logs)
- `CLOUDFLARE_TUNNEL_TOKEN` (optional GitHub Actions secret for a stable named Cloudflare Tunnel; recommended after Quick Tunnel HTTP 429 errors)
- `CLOUDFLARE_TUNNEL_HOSTNAME` (GitHub Actions repository variable; the public hostname configured in the named tunnel to route to `http://127.0.0.1:8080`)

## Current integration caveats (2026-11-28)

- The browser workflow currently opens three protected tabs. BlackBit and Winance are fetched through their public HTTPS GET APIs. This is more lightweight than five browser tabs but differs from the original five-tab requirement; resolve this explicitly before merging PR #34.
- The integrated collection workflow is manual-only. It requires the authenticated encrypted Chromium profile and current-run snapshots from all three protected browser sources. A complete end-to-end live run has not yet been performed after the new read-only guards.
- Money Storage and Sberkassa quote requests are GET-only. Non-GET requests are blocked and not replayed. If the provider's current UI requires POST for its quote feed, the collector will fail closed.
- The route result is normalized to 1 USDT and labelled pre-fee. It is not based on a user-selected starting capital and is not net profit.
